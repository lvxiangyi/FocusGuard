# FocusGuard MVP 实装

本分支正式界面采用 `docs/demos/mvp-v1` 的桌面布局。静态 demo 保留原标签，正式应用从 `frontend/src/App.jsx` 进入。

## 使用

关闭旧版 FocusGuard 后运行根目录 `start_stable.bat`。前端已构建到 `frontend/dist`；后端仍需按原有方式在 `.env` 配置所选供应商的 API key。

- **专注**：输入任务，选择 25/45/60 分钟，开始或结束。计时与检查状态来自后端；拦截期间冻结计时。
- **最近判定**：查看真实历史截图和判断，选择实际在做任务或分心，填写原因后保存。
- **我的案例**：查看、删除 Session 的训练案例；test 集不作为产品入口，也不进入检索。
- **偏好设置**：恢复方式可选快速返回（默认）、写下下一步行动或翻译练习；仅选择翻译时显示目标语言。界面与翻译目标语言分别支持中/英/日/韩/法/葡，检查频率、连续命中阈值与 AI 模型放在折叠设置内。
- **系统拦截**：原有 tkinter 常驻窗口按偏好显示恢复界面。快速返回一次确认即可继续；下一步行动必须填写后继续；翻译练习由真实模型判分，查看答案不算通过，需换句重试。
- **截图热键**：Ctrl+Alt+1 标记“做任务”，Ctrl+Alt+2 标记“分心”，之后在最近判定页补充任务和原因。这两个热键表示实际状态，不表示是否同意原 AI 判断。拦截期间请用拦截页的纠正入口，以免截到拦截窗口本身。

## MVP 行为边界

- 只有手动 Session 运行监督；启动时不运行 Guardian、自动日程或 Flow 恢复。旧数据和模块保留。
- Session 固定使用 task_related 监督；恢复方式默认为快速返回，也可改为填写下一步或翻译挑战。允许主动结束，不再弹出工作/休息/停止流程。
- 新翻译入口使用内置英文句子；目标为英文时改用中文原句。自定义题库上传不在本 MVP 范围内，旧题库数据没有删除。
- 个人案例是判断参考；保存案例不等于异议审核通过，也不会解除当前拦截。
- 任务、用户标注和已有历史记录保留原文。新模型判定理由、翻译反馈和解析按当前界面语言生成。

## 正确性措施

- 服务端绑定 `session_id + block_id + challenge_id`，客户端不能自行提交原句或目标语言改写当前挑战；过期题目不能解锁新一轮。
- 停止或替换任务后，未完成模型请求的结果不会应用到下一轮；模型返回时已到期则结束，不再弹拦截。
- 无 API key、API 错误、格式错误均不作为通过；模型 `accepted` 必须为布尔值。查看答案只标记跳过，不能提交复制的参考答案解锁原题。
- 翻译请求在工作线程执行；仅 Tk 队列更新窗口。模型判分期间仍可结束任务，旧窗口回调失效后不会操作新窗口。
- 反馈使用服务端历史记录的任务和截图，限制在数据目录；保存/删除案例或更改设置使判定缓存失效，包括正在进行的旧判定。
- 样本文件由跨实例线程锁保护。历史按时间排序，缺失截图不会被错误替换或排到其他时间位置。
- 前端不会把模拟状态或参考译文匹配用于真实产品；引用数来自实际检索结果。
